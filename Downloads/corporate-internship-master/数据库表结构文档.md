## 一、核心业务表（11个）

### 1. kanban - 看板表

**功能：** 存储所有看板信息，支持入库、出库、转包等业务场景

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| kanban_no | VARCHAR(100) | UNIQUE, NOT NULL | - | 看板号（全局唯一） |
| order_no | VARCHAR(50) | NOT NULL | - | 关联单据号（PO-/IO-/SO-开头） |
| part_code | VARCHAR(100) | NOT NULL | - | 零件号 |
| part_name | VARCHAR(200) | NULL | NULL | 零件名称 |
| supplier_code | VARCHAR(50) | NULL | NULL | 供应商代码 |
| warehouse_code | VARCHAR(50) | NULL | NULL | **仓库代码** |
| quantity | INT | NULL | 0 | 数量 |
| box_count | INT | NULL | 1 | 箱数 |
| qr_code | TEXT | NULL | NULL | 二维码内容 |
| status | VARCHAR(20) | NULL | 'pending' | 状态：pending/stored/outbound |
| scan_time | DATETIME | NULL | NULL | 扫码时间 |
| scan_by | VARCHAR(50) | NULL | NULL | 扫码人 |
| created_at | DATETIME | NULL | CURRENT_TIMESTAMP | 创建时间 |
| is_sealed | TINYINT | NULL | 0 | 是否封存：0-未封存，1-已封存 |
| original_quantity | INT | NULL | NULL | 原始数量（转包时使用） |
| transfer_type | VARCHAR(20) | NULL | NULL | 转包类型：split-拆分，merge-合并 |
| parent_kanban_no | VARCHAR(100) | NULL | NULL | 父看板号（转包时使用） |

**索引：**
- 主键索引：`id`
- 唯一索引：`kanban_no`

**业务说明：**
- 看板号格式：`KAN-{timestamp}-{零件代码}-{序号}`
- 状态流转：pending（待入库）→ stored（已入库）→ outbound（已出库）
- 转包拆分会创建新看板，`transfer_type='split'`，记录`parent_kanban_no`
- 转包合并会创建新看板，`transfer_type='merge'`

### 2. current_inventory - 当前库存表

**功能：** 实时记录当前在库的看板库存信息

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| kanban_no | VARCHAR(100) | UNIQUE, NOT NULL | - | 看板号（唯一） |
| part_code | VARCHAR(100) | NOT NULL | - | 零件号 |
| part_name | VARCHAR(200) | NULL | NULL | 零件名称 |
| supplier_code | VARCHAR(50) | NULL | NULL | 供应商代码 |
| quantity | INT | NULL | 0 | 当前库存数量 |
| warehouse_code | VARCHAR(50) | NULL | NULL | **仓库代码** |
| status | VARCHAR(20) | NULL | 'stored' | 状态：stored/sealed |
| created_at | DATETIME | NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NULL | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**索引：**
- 主键索引：`id`
- 唯一索引：`kanban_no`

**业务说明：**
- 入库时创建记录，出库时删除记录
- `quantity > 0` 表示有库存，`= 0` 表示已出库
- 封存操作不删除记录，仅修改`status='sealed'`

### 3. inventory_trace - 库存追溯表（全部流水）

**功能：** 记录所有库存操作历史，支持完整追溯

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| trace_no | VARCHAR(100) | NOT NULL | - | 追溯号（唯一标识） |
| kanban_no | VARCHAR(100) | NULL | NULL | 看板号 |
| order_no | VARCHAR(50) | NULL | NULL | 单据号 |
| part_code | VARCHAR(100) | NULL | NULL | 零件号 |
| part_name | VARCHAR(200) | NULL | NULL | 零件名称 |
| supplier_code | VARCHAR(50) | NULL | NULL | 供应商代码 |
| quantity | INT | NULL | 0 | 操作数量 |
| warehouse_code | VARCHAR(50) | NULL | NULL | **仓库代码** |
| action_type | VARCHAR(20) | NULL | NULL | **操作类型** |
| action_time | DATETIME | NULL | CURRENT_TIMESTAMP | 操作时间 |
| operator | VARCHAR(50) | NULL | NULL | 操作人 |
| remark | TEXT | NULL | NULL | 备注说明 |

**索引：**
- 主键索引：`id`

**action_type 操作类型枚举：**

| 值 | 说明 | 颜色标签 | 触发场景 |
|---|------|---------|---------|
| `INBOUND` | 入库 | 🟢 绿色 | 扫码入库完成 |
| `OUTBOUND` | 出库 | 🟠 橙色 | 扫码出库完成 |
| `TRANSFER_SPLIT` | 转包拆分 | 🔵 蓝色 | 看板拆分操作 |
| `TRANSFER_MERGE` | 转包合并 | 🔵 蓝色 | 看板合并操作 |
| `SEAL` | 封存 | 🔴 红色 | 看板封存操作 |
| `UNSEAL` | 解封 | ⚪ 默认色 | 看板解封操作 |

**追溯号格式：**
- 入库：`TRACE-IN-{timestamp}-{kanban_no}`
- 出库：`TRACE-OUT-{timestamp}-{kanban_no}`
- 转包拆分：`TRACE-SPLIT-{timestamp}-{kanban_no}`
- 转包合并：`TRACE-MERGE-{timestamp}-{kanban_no}`
- 封存：`TRACE-SEAL-{timestamp}-{kanban_no}`
- 解封：`TRACE-UNSEAL-{timestamp}-{kanban_no}`

### 4. inbound_order - 入库单表

**功能：** 管理入库单主信息

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| order_no | VARCHAR(50) | UNIQUE, NOT NULL | - | 入库单号 |
| inbound_type | VARCHAR(50) | NOT NULL | - | 入库类型 |
| supplier_code | VARCHAR(50) | NOT NULL | - | 供应商代码 |
| warehouse_code | VARCHAR(50) | NULL | NULL | **仓库代码** |
| status | VARCHAR(20) | NULL | 'pending' | 状态：pending/scanning/completed |
| total_quantity | INT | NULL | 0 | 总数量（所有明细预期数量之和） |
| received_quantity | INT | NULL | 0 | 已收数量 |
| total_boxes | INT | NULL | 0 | 总箱数（所有明细预期箱数之和） |
| received_boxes | INT | NULL | 0 | 已收箱数 |
| remark | TEXT | NULL | NULL | 备注 |
| created_by | VARCHAR(50) | NULL | NULL | 创建人 |
| created_at | DATETIME | NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NULL | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**索引：**
- 主键索引：`id`
- 唯一索引：`order_no`

**入库单号格式：** `PO-{YYYYMMDD}-{序号}` 或 `IO-{YYYYMMDD}-{序号}`

**状态流转：**
- `pending`（待入库）→ `scanning`（扫码中）→ `completed`（已完成）

### 5. inbound_order_detail - 入库单明细表

**功能：** 记录入库单的明细行信息

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| order_no | VARCHAR(50) | INDEX | - | 入库单号 |
| part_code | VARCHAR(100) | NOT NULL | - | 零件号 |
| part_name | VARCHAR(200) | NULL | NULL | 零件名称 |
| expected_quantity | INT | NULL | 0 | 预期数量 |
| received_quantity | INT | NULL | 0 | 已收数量 |
| packaging_capacity | INT | NULL | 0 | 包装容量（每箱数量） |
| expected_boxes | INT | NULL | 0 | 预期箱数 |
| received_boxes | INT | NULL | 0 | 已收箱数 |
| unit | VARCHAR(10) | NULL | '个' | 单位 |

**索引：**
- 主键索引：`id`
- 普通索引：`order_no`

**业务说明：**
- 一个入库单可以包含多个明细行（不同零件）
- `expected_boxes = CEILING(expected_quantity / packaging_capacity)`

### 7. outbound_order_detail - 出库单明细表

**功能：** 记录出库单的明细行信息

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| order_no | VARCHAR(50) | INDEX | - | 出库单号 |
| part_code | VARCHAR(100) | INDEX | - | 零件号 |
| part_name | VARCHAR(200) | NULL | NULL | 零件名称 |
| expected_quantity | INT | NULL | 0 | 预期数量 |

| packaging_capacity | INT | NULL | 0 | 包装容量 |

| shipped_boxes | INT | NULL | 0 | 已发箱数 |
| unit | VARCHAR(10) | NULL | '个' | 单位 |

**索引：**
- 主键索引：`id`
- 普通索引：`order_no`, `part_code`

**业务说明：**
- 出库明细不含看板号，通过FIFO算法动态匹配入库看板
- 匹配规则：按`created_at`和`id`排序，先进先出

### 8. transfer_order - 转包单表

**功能：** 记录看板转包（拆分/合并）操作

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 主键ID |
| order_no | VARCHAR(50) | UNIQUE, NOT NULL | - | 转包单号 |
| from_kanban_no | VARCHAR(100) | INDEX, NOT NULL | - | 源看板号 |
| to_kanban_nos | TEXT | NULL | NULL | 目标看板号列表（JSON数组） |
| transfer_type | VARCHAR(20) | NOT NULL | - | 转包类型：split/merge |
| original_quantity | INT | NOT NULL | - | 原始数量 |
| new_quantities | TEXT | NOT NULL | - | 新数量列表（JSON数组） |
| status | VARCHAR(20) | INDEX | 'pending' | 状态：pending/completed |
| operator | VARCHAR(50) | NULL | NULL | 操作人 |
| remark | TEXT | NULL | NULL | 备注 |
| created_at | DATETIME | NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NULL | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

**索引：**
- 主键索引：`id`
- 唯一索引：`order_no`
- 普通索引：`from_kanban_no`, `status`

**转包类型：**
- `split`（拆分）：一个看板拆分成多个看板
- `merge`（合并）：多个看板合并成一个看板

**JSON字段示例：**
```json
// to_kanban_nos（拆分）
["KAN-1234567890-A-1", "KAN-1234567890-A-2"]

// new_quantities（拆分）
[30, 20]
```

## 六、核心字段说明

### 1. warehouse_code（仓库代码）分布

以下表包含`warehouse_code`字段，用于标识仓库归属：

| 表名 | 用途 | 示例值 |
|------|------|--------|
| warehouse | 仓库定义表 | WH-A, WH-B |
| kanban | 看板表 | WH-A |
| current_inventory | 当前库存表 | WH-A |
| inventory_trace | 库存追溯表 | WH-A |
| inbound_order | 入库单表 | WH-A |
| outbound_order | 出库单表 | WH-A |
| storage_location | 库位表（废弃） | WH-A |

### 2. 单据号命名规则

| 单据类型 | 前缀 | 格式 | 示例 |
|---------|------|------|------|
| 入库单（采购） | PO- | PO-{YYYYMMDD}-{序号} | PO-20260622-0001 |
| 入库单（其他） | IO- | IO-{YYYYMMDD}-{序号} | IO-20260622-0001 |
| 出库单 | SO- | SO-{YYYYMMDD}-{序号} | SO-20260622-0001 |
| 转包单 | TR- | TR-{YYYYMMDD}-{序号} | TR-20260622-0001 |
| 看板号 | KAN- | KAN-{timestamp}-{零件代码}-{序号} | KAN-1782126292932-A-6 |
| 追溯号 | TRACE- | TRACE-{类型}-{timestamp}-{看板号} | TRACE-IN-1234567890-KAN-xxx |

### 3. 状态枚举值

**入库单/出库单状态：**
- `pending` - 待处理
- `scanning` - 扫码中
- `completed` - 已完成

**看板状态：**
- `pending` - 待入库
- `stored` - 已入库
- `outbound` - 已出库

**库存状态：**
- `stored` - 在库
- `sealed` - 已封存

**转包类型：**
- `split` - 拆分
- `merge` - 合并

## 七、业务流程说明

### 1. 入库流程

```
创建入库单（inbound_order）
    ↓
添加入库明细（inbound_order_detail）
    ↓
生成看板（kanban）
    ├─ 从入库单获取 warehouse_code
    └─ 状态：pending
    ↓
扫码入库
    ├─ 更新看板状态：pending → stored
    ├─ 创建库存记录（current_inventory）
    └─ 记录追溯（inventory_trace, action_type=INBOUND）
    ↓
更新入库单进度
    └─ received_quantity, received_boxes
    ↓
完成入库
    └─ status = completed
```

### 2. 出库流程

```
创建出库单（outbound_order）
    ↓
添加出库明细（outbound_order_detail）
    ↓
扫码出库
    ├─ FIFO匹配入库看板
    │   └─ 按 created_at, id 排序，优先匹配早入库的
    ├─ 验证库存（current_inventory.quantity）
    ├─ 扣减库存
    ├─ 更新看板状态：stored → outbound
    ├─ 删除库存记录（current_inventory）
    └─ 记录追溯（inventory_trace, action_type=OUTBOUND）
    ↓
更新出库单进度
    └─ shipped_quantity, shipped_boxes
    ↓
完成出库
    └─ status = completed
```

### 3. 转包流程（拆分）

```
选择源看板
    ↓
指定拆分数量和数量分配
    ↓
创建转包单（transfer_order, transfer_type=split）
    ↓
执行拆分
    ├─ 更新源看板：quantity=0, is_sealed=1
    ├─ 删除源库存记录
    ├─ 创建新看板（多个）
    │   ├─ transfer_type = 'split'
    │   ├─ parent_kanban_no = 源看板号
    │   └─ warehouse_code = 继承源看板
    ├─ 创建新库存记录（多个）
    ├─ 记录追溯（TRANSFER_SPLIT）
    └─ 更新转包单状态：completed
```

### 4. 转包流程（合并）

```
选择多个源看板（同零件、同供应商）
    ↓
创建转包单（transfer_order, transfer_type=merge）
    ↓
执行合并
    ├─ 更新源看板：quantity=0, is_sealed=1
    ├─ 删除源库存记录
    ├─ 创建新看板（1个）
    │   ├─ quantity = 源看板数量之和
    │   ├─ transfer_type = 'merge'
    │   └─ warehouse_code = 继承源看板
    ├─ 创建新库存记录
    ├─ 记录追溯（TRANSFER_MERGE）
    └─ 更新转包单状态：completed
```

### 5. 封存/解封流程

```
选择看板
    ↓
执行封存/解封
    ├─ 更新看板：is_sealed = 1（封存）或 0（解封）
    ├─ 更新库存：status = 'sealed' 或 'stored'
    ├─ 记录封存历史（seal_history）
    └─ 记录追溯（inventory_trace）
        ├─ action_type = 'SEAL' 或 'UNSEAL'
        └─ remark = 备注信息
```
